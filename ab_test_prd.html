AB 测试平台开发需求文档

建立一套通用的 AB 测试配置平台，内置于18GAME后台。运营人员可以自由选择要测试的页面板块，自行配置对照组和实验组的内容变量，系统负责用户分流、下发对应版本，并提供数据看板对比两组效果差异。

01 /

定位与目标

1.1 背景与目的

目前平台各页面的内容配置（如首页 Banner、充值套餐排列、游戏推荐位、弹窗文案等）调整后无法量化效果，运营只能靠经验判断。AB 测试平台的目标是让运营可以科学地验证任何一处页面改动的实际效果——先在一部分用户中测试新版本，对比关键指标差异，数据说话后再决定是否全量推出。

1.2 核心定位

这是一个通用的 AB 测试配置工具，不绑定任何特定的业务场景。运营可以用它测试平台内任意页面的任意板块，包括但不限于：

💰
充值页
套餐排列顺序、价格展示方式、VIP与G点的优先展示位置、新人专属价格
🏠
首页
Banner 图片/文案、推荐游戏排列、弹窗触发时机、活动入口位置
🎮
游戏详情页
下载按钮文案、价格标注方式、截图排列顺序、推荐相关游戏的展示逻辑
🎁
活动页
活动规则文案、奖励展示方式、参与引导步骤、倒计时样式
👤
个人中心
会员权益展示方式、充值入口引导文案、签到/积分模块位置
📢
引导弹窗
注册后引导弹窗内容、首次进入充值页的提示文案、新人任务引导顺序

1.3 功能范围

  • 支持：运营自定义试验名称、选择测试板块、配置对照组和实验组的变量值
  • 支持：四种固定分群条件（新用户/老用户/充值过/未充值），每次试验选一种
  • 支持：试验完整生命周期管理（创建/上线/暂停/结束/复制）
  • 支持：以点击/曝光为核心的数据看板，对比两组用户的行为差异

1.4 核心术语

试验
一次 AB 测试的完整单元，有唯一编号、完整生命周期（草稿→运行中→已结束）和独立的数据看板。每个试验只测试一个变量。
测试板块
运营选择要进行 AB 测试的页面区域，例如「充值页-套餐排列」「首页-Banner」「游戏详情页-下载按钮文案」。测试板块决定了前端在哪个位置读取 AB 分组结果并展示对应版本。
变量
在选定的测试板块中，对照组和实验组之间唯一不同的那个配置项。每次试验只允许改变一个变量，其余保持一致，确保测试结论的可靠性。
对照组（Control）
基准方案，使用当前线上已有的版本配置，作为衡量实验组效果的参照基准。
实验组（Experiment）
待验证的新版本，配置希望测试的新内容，与对照组的变量值必须不同。
分群
筛选哪些用户有资格参与本次试验的条件。支持四种固定分群，每个试验只能选一种。不在分群内的用户不参与试验，始终看默认版本。
命中
用户满足试验的全部参与条件（试验运行中+在生效时间内+满足分群），系统将其分配到对照组或实验组的行为。一旦命中，全程固定在同一组。
默认版本
用户未命中任何试验时，页面展示的原始配置版本。暂停或结束试验后，所有用户立即回退到默认版本。

状态与流转规则

3.1 状态流转

● 草稿→ 上线 → ● 运行中→ 暂停 → ● 暂停→ 重新上线 → ● 运行中→ 结束 → ● 已结束

注：运行中可直接结束，无需先暂停

状态含义前端展示用户侧行为可执行操作
草稿已创建但未上线，配置中灰色标签无影响，所有用户看默认版本编辑、上线、复制、删除
运行中试验进行中，正在对用户生效绿色标签命中用户看对应组版本；未命中看默认版本暂停、结束、查看数据、复制；禁止编辑
暂停试验暂停，停止对用户分流橙色标签所有用户立即回退到默认版本编辑、重新上线、结束、查看数据、复制
已结束试验归档，永久终止灰色标签所有用户回退到默认版本查看数据、复制

3.2 关键约束

  • 同一时间只允许一个试验处于运行中——上线新试验前，系统自动检查是否存在其他运行中的试验，若存在则拦截并提示，同时展示当前运行中的试验名称和跳转链接
  • 运行中禁止编辑——必须先暂停才能修改任何配置，修改后重新校验上线
  • 暂停/结束后立即生效——执行操作后，用户下次访问对应页面时立即看到默认版本，不存在延迟
  • 结束操作不可撤回——结束后数据永久保留可查看，但试验不可再次激活，只能复制为新草稿

3.3 状态变更日志

每次状态变更需记录操作日志：试验编号、变更前状态、变更后状态、操作人（自动结束填「system」）、操作时间。用于审计和问题排查。

分群与命中规则

4.1 固定分群定义

分群名称判断逻辑判断字段适用场景
新用户注册时间晚于试验开始时间register_time > experiment_start_time测试对新注册用户的引导内容、首充激励方式
老用户注册时间早于或等于试验开始时间register_time ≤ experiment_start_time测试对存量用户的活跃/复购激励内容
充值过用户历史存在至少1笔支付成功的充值订单paid_order_count > 0测试对已付费用户的高价值内容推荐或套餐升级引导
未充值用户历史不存在任何支付成功的充值订单paid_order_count = 0测试对从未付费用户的首充转化引导内容
单选限制：每个试验只能选择一种固定分群，不支持多选或组合条件。分群在试验创建时确定，上线后不可修改（需先暂停）。

4.2 命中规则（三个条件同时满足）

条件 1
试验状态为运行中——草稿、暂停、已结束状态的试验不对任何用户生效
条件 2
当前时间在生效时间范围内——若设置了开始时间，需 current_time ≥ start_time；若设置了结束时间，需 current_time ≤ end_time
条件 3
用户满足该试验的固定分群条件——不满足分群的用户不参与试验，接口返回 hit: false，页面展示默认版本

4.3 分流算法

分流算法规格
算法基于用户ID + 试验ID的哈希取模，同一用户在同一试验中始终落在同一组，不会因刷新、换设备（登录状态下）而变化
具体实现bucket = MD5(user_id + "_" + experiment_id) 的整数值对2取模；结果为0 → 对照组；结果为1 → 实验组
分组单元必须使用用户ID，禁止使用Session ID或Cookie——同一用户清缓存、换浏览器后Session会变化，导致分组漂移，数据污染
未登录用户未登录用户没有user_id，不参与任何试验，接口返回 hit: false，展示默认版本
分组缓存分组结果缓存于Redis：Key为 ab:group:{experiment_id}:{user_id}，TTL设置为试验结束时间+1小时
跨试验独立用户在不同试验中的分组完全独立，互不影响

4.4 SRM 分组完整性检查

建议实现：后端每天定时对所有运行中的试验执行卡方检验，检验实际两组用户数与预期50/50的偏差。p值 < 0.01 判定为异常，在数据看板顶部展示警告：「⚠️ 当前试验两组用户比例存在显著偏差（对照组:实验组 = X:Y），数据结论可能不准确，请排查分组逻辑。」

试验配置规则

5.1 测试板块与变量配置

每个试验包含三个核心配置项：测试板块（测哪里）、对照组变量值（原来是什么）、实验组变量值（新版本是什么）。

配置项说明示例
测试板块选择要进行AB测试的页面区域。系统维护一个板块列表，运营从中选择，也可申请新增板块（需技术配合前端接入）。板块名称应清晰描述位置，如「充值页-套餐排列」「首页-顶部Banner」充值页-套餐排列、首页-顶部Banner、游戏详情页-下载按钮文案
对照组变量值该板块当前线上正在使用的版本配置，作为基准。变量值的格式由具体板块决定，可以是文字、图片链接、配置JSON等「立即下载」、套餐ID列表[A,B,C]、Banner图片URL
实验组变量值想要验证效果的新版本配置，必须与对照组变量值不同「免费体验」、套餐ID列表[B,C,A]、新Banner图片URL

5.2 板块类型与变量格式

板块类型变量值格式前端读取方式示例场景
文案类纯文本字符串直接替换对应位置的显示文字按钮文案、标题文案、引导语
图片类图片URL或图片ID替换对应位置的图片资源Banner图片、活动海报、游戏封面
排列顺序类ID数组，如 [id1,id2,id3]按数组顺序渲染对应内容列表套餐排列顺序、推荐游戏顺序
开关类布尔值 true/false控制某个功能模块是否展示是否展示倒计时、是否展示会员角标
配置JSON类JSON对象字符串解析JSON后渲染对应的复合内容弹窗的标题+内容+按钮文案组合配置
单变量原则：每次试验只允许改变一个变量，对照组和实验组其余所有配置保持完全一致。同时改变多个变量会导致无法判断是哪个因素影响了结果。如果确实需要测试多个变量，应创建多个独立的试验，分批测试。

新建与编辑流程

7.1 新建入口

试验列表页右上角「+ 新建试验」按钮，点击后以侧滑抽屉或全屏表单打开，分两步填写。

7.2 第一步：基本信息

字段必填说明校验规则
试验名称必填建议格式：「页面-测试内容-日期」，如「充值页-套餐顺序-0501」不能为空，最长50字符
负责人必填运营人员姓名或账号不能为空
试验假设选填说明本次试验要验证的假设，如「假设把免费体验按钮放在首位，新用户点击率会高于立即下载」。填写后便于复盘时理解背景。最长200字符
生效方式必填「立即生效」：上线后立即对符合分群的用户生效
「指定开始时间」：到达设定时间后自动开始		指定时间需晚于当前时间
结束方式必填「手动结束」：运营手动点击结束
「指定结束时间」：到达时间后系统自动结束		指定时间需晚于开始时间

7.3 第二步：分群与试验配置

字段必填说明
固定分群必填单选：新用户 / 老用户 / 充值过用户 / 未充值用户
每个选项旁展示分群定义说明
测试板块必填从系统维护的板块列表中选择，展示板块名称+所属页面+变量类型
选中后下方展示该板块的变量格式说明，帮助运营正确填写变量值
对照组配置必填根据选择的板块类型展示对应的输入控件：
文案类→文本输入框；图片类→图片上传/URL输入；排列类→拖拽排序；开关类→开关按钮；JSON类→JSON编辑器
实验组配置必填与对照组配置控件类型一致；提交时检测两组值是否相同，相同时即时报错
板块说明提示：运营选择某个板块后，系统在配置区域顶部展示该板块的说明信息：所属页面、变量格式要求、填写示例、以及该板块的埋点事件名称（方便后续在看板中查看对应数据）。

7.4 编辑与复制

编辑仅在草稿和暂停状态下可用，打开与新建相同的两步表单并预填当前配置。暂停状态下可选「保存并重新上线」，会重新执行全部上线前校验。

复制操作将所有配置复制为新草稿，试验名称加「-副本」后缀，时间字段重置为「立即生效+手动结束」，数据看板为空。

08 /

数据看板

8.1 看板入口

在试验列表页点击「查看数据」进入该试验的数据看板。运行中、暂停、已结束状态均可查看。草稿状态无数据，不展示入口。

8.2 看板顶部信息（只读）

  • 试验名称、编号、当前状态、负责人
  • 测试板块名称 + 所属页面
  • 对照组配置内容 / 实验组配置内容（展示运营填写的变量值）
  • 固定分群、试验时间范围
  • 试验假设（若填写了则展示）

8.3 核心指标（通用）

以下指标适用于所有板块类型，对照组和实验组并排展示，每个指标下方展示实验组相对对照组的变化百分比。

曝光人数
Impression UV
看到该板块的去重用户数。衡量两组用户中有多少人实际触达到了测试内容。
曝光次数
Impression PV
该板块被展示的总次数，含同一用户多次访问。
点击人数
Click UV
点击过该板块任意交互元素的去重用户数。
点击次数
Click PV
该板块被点击的总次数，含同一用户多次点击。
点击率
Click UV ÷ Impression UV
曝光用户中实际发生点击的比例。这是判断「实验版本是否更能吸引用户点击」的核心指标。
人均点击次数
Click PV ÷ Click UV
点击用户的平均点击次数。数值偏高说明用户在该区域有反复操作行为。

8.4 业务转化指标（按板块类型扩展）

除通用指标外，各板块可根据其业务目标配置额外的转化指标，由技术在板块接入时定义对应的埋点事件。

板块类型示例扩展转化指标对应埋点事件
充值页-套餐配置创建订单数、实付订单数、实付金额、支付转化率、客单价order_create、order_pay
首页-BannerBanner跳转点击率、跳转后页面停留时长、跳转后转化率banner_click、page_stay
游戏详情页-下载按钮下载点击率、下载完成率、下载后首次启动率download_click、download_complete
引导弹窗弹窗关闭率、引导完成率、引导后付费转化率popup_close、guide_complete
指标扩展机制：每个板块在系统中注册时，同时配置该板块关联的业务转化埋点事件名称列表。看板会自动拉取这些事件的数据并计算对应指标，无需每次新建试验时手动配置。

8.5 时序折线图

  • 支持「按天」和「按小时」切换，默认按天展示
  • 对照组和实验组各一条折线，颜色区分
  • 支持选择展示的指标，默认展示「点击率」
  • 鼠标悬停展示气泡提示：该时间点两组各自的指标值及差异百分比
  • 若试验曾被暂停，暂停时间段用灰色区域标注；结束时间点用虚线标注
注意时间周期性波动：平台周末日活明显高于工作日，若试验刚好跨越周末，看板数据可能受到流量波动影响。建议至少运行7天（覆盖一个完整的周内周期）再下结论，通过时序图识别波动规律。

8.6 明细数据与导出

看板底部展示按天（或小时）的明细数据表格，支持导出为CSV，包含所有统计字段的原始数据。

09 /

暂停与结束

9.1 暂停

触发方式
列表页点击「暂停」，弹出二次确认：「确定暂停该试验？暂停后所有用户将立即看到默认版本，试验数据保留。」双按钮：「取消」/ 「确认暂停」
生效时机
立即生效——后端将试验状态改为暂停，前端接入接口立即停止返回该试验的分组信息，用户下次访问对应页面时即看到默认版本，不存在延迟
暂停后操作
暂停状态下可编辑所有配置，编辑完成后选择「保存并重新上线」，重新执行全部上线前校验通过后恢复运行

9.2 结束

触发方式
列表页点击「结束」，弹出不可撤回警告：「确定结束该试验？结束后不可重新上线，历史数据仍可查看。此操作不可撤回。」双按钮：「取消」/ 红色「确认结束」
生效时机
立即生效，行为与暂停一致——所有用户立即回退默认版本，状态改为已结束
后续迭代
可复制为新草稿，修改实验组配置后重新上线。推荐工作流：测试→得出结论→复制→调整配置→再次测试

9.3 自动结束

若设置了指定结束时间，后端通过定时任务（建议每分钟轮询）自动将到期试验状态改为已结束，行为与手动结束完全一致。自动结束后向创建人发送站内信通知。

前端接入规范

10.1 AB 分组接口

接口规格（建议）
接口路径GET /api/ab/experiment
请求参数user_id（必传）、module（必传，测试板块标识，如 recharge_package、home_banner）
响应结构 命中试验：{"hit": true, "experiment_id": "xxx", "group": "control"/"experiment", "value": "对应组的变量值"}
未命中/未登录：{"hit": false, "value": "该板块的默认值"}
超时阈值建议200ms；超时后降级展示默认版本，不阻塞页面渲染
降级策略接口超时、异常、服务不可用时，均降级返回默认值，保证页面正常展示

10.2 前端接入流程

1
页面加载时请求 AB 分组接口
传入 user_id 和当前页面的 module 标识，获取分组结果和对应的变量值。未登录用户不传 user_id，接口返回默认值。
2
根据返回的 value 渲染对应版本
前端直接使用接口返回的 value 渲染对应板块，对用户不展示任何「你在参与AB测试」的提示。前端不做任何分组判断逻辑，只消费接口返回的值。
3
用户产生交互时上报埋点
用户点击、曝光等行为发生时，埋点事件需携带：user_id、module、event_type（如 click/impression）
若命中试验额外携带：experiment_id、group（control/experiment）
未命中试验时不传 experiment 相关字段
4
新增板块接入流程
运营希望对某个新板块做AB测试时，需先由技术人员完成该板块的接入工作：①在系统中注册板块（配置板块名称、module标识、变量格式、关联的业务埋点事件）；②前端在对应位置接入AB接口调用；③前端在用户交互时携带 experiment_id 和 group 上报埋点。完成后运营即可在后台创建该板块的试验。
严禁前端分组：禁止在页面前端代码中实现分组判断逻辑（如根据user_id奇偶决定展示哪个版本）。分组必须由后端统一处理，前端只消费接口返回的变量值。原因：前端逻辑可被用户绕过；前端代码修改后无法对已分组用户生效；分组结果无法被正确记录统计。

12.2 边界情况

板块未接入
运营选择了某个板块创建并上线试验，但该板块前端尚未完成AB接入（即从未调用过AB分组接口传入该module），此时试验运行中但实际没有任何用户被分组，看板数据全为0。需在板块注册时注明接入状态，避免运营对未接入板块创建试验。
用户身份变化
用户首次触达该板块时完成分群判断并分组，结果写入Redis缓存。此后用户身份发生变化（如未充值用户完成了首充），分组结果不会变化——这是正确行为，保证了分组一致性。
同一用户满足多个分群
一个用户可能同时满足多个分群条件（如既是老用户又是充值过用户），但由于同一时间只有一个运行中的试验，不会出现「命中多个试验」的情况，无需处理。
大量并发请求
高峰期（如活动期）充值页等热门板块请求量急剧上升，Redis缓存应覆盖大部分请求。若Redis不可用，降级为直接查数据库（加超时保护），最终兜底为返回默认值。
